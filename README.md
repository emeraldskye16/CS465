# CS465
This project represents the completed Travlr Getaways application, with both a customer-facing Express site and an administrative Angular SPA. I worked with two frontend approaches: server-rendered Express HTML and the dynamic Angular SPA. The Express side uses Handlebars templates and traditional routing, where each page is rendered on the server and refreshed on navigation. In contrast, the Angular admin interface is entirely client-side, built with reusable components, TypeScript logic, and internal routing, allowing the application to update without reloading the page. This architecture provides a smoother, more interactive experience for administrative tasks. The backend uses a NoSQL MongoDB database because its flexible, document-based structure aligns naturally with the JSON data exchanged between the API and both frontends. MongoDB’s schema-less design also makes it easier to evolve the data model as features grow, without the rigid migrations required by relational databases.

JSON played a central role in connecting the frontend and backend. Unlike JavaScript, which is a full programming language capable of logic and behavior, JSON is a lightweight data format used strictly for structured data exchange. The API returns JSON responses that Angular consumes and converts into TypeScript models, while Express also uses JSON for POST and PUT requests. This consistent format allowed both frontends to communicate seamlessly with the backend. Throughout the project, I refactored code to improve clarity and efficiency by consolidating API logic into Angular’s TripDataService and creating reusable UI components, such as TripCardComponent. These changes reduced duplication, improved maintainability, and made the application easier to scale. Reusable components also ensured consistent styling and behavior across the admin interface, which is especially valuable in larger applications.

Testing the application required validating API endpoints using tools like the browser, Postman, and Angular’s network inspector. I tested GET, POST, PUT, and DELETE methods to ensure the API behaved correctly and returned the expected JSON data. When authentication was added, testing became more complex because protected routes required valid JWT tokens. This added layers of verification, including ensuring that Angular attached authorization headers correctly and that unauthorized requests returned appropriate error responses. Understanding how methods, endpoints, and security interact in a full-stack application was essential for reliable communication between the SPA and the backend.

Overall, this course significantly advanced my professional skills and confidence as a full-stack developer. It showed that I can strengthen my understanding of the MEAN stack, learn how to build and structure an Angular SPA, and gain hands-on experience with API design, authentication, and database integration. I also developed stronger debugging skills by working through real-world issues such as CORS errors, routing mismatches, and service-layer bugs. These experiences have made me a more capable and marketable candidate in the software development field, especially for roles involving modern JavaScript frameworks and full-stack application architecture.
